User guide and technical reference

AOVGuard documentation

AOVGuard validates OpenEXR files and render sequences. It detects read errors, NaN values, infinities, empty AOVs, unknown channels, temporal changes, and continuity problems without hiding unrecognized data.

Verified status: 282 tests passed with 95.37% combined statement and branch coverage on Python 3.12.

Installation

Windows or Linux, Python 3.12, and uv are recommended. The project supports Python 3.11 and 3.12.

cd "C:\path\AOVGuard"
python -m pip install uv
uv python install 3.12
uv sync --python 3.12 --extra dev

After synchronizing the environment:

uv run aovguard-ui
uv run aovguard --help
Important: AOVGuard does not create demonstration EXRs during installation or analysis. The examples directory remains empty except for its version-control placeholder.

Using the graphical interface

  1. Select the source. Use File for one EXR or Folder for a sequence.
  2. Load an optional preset. Presets can be TOML or JSON. Without one, the default rules are applied.
  3. Choose the luminance model. Rec.709 is the usual choice; Rec.601 and custom weights are also available.
  4. Set the source mode. Auto infers the type; Sequence requires numbered frames; Comparison treats EXRs as independent samples.
  5. Review discovery settings. Adjust the pattern, recursive search, depth, multiple sequences, frame limit, and expected range.
  6. Use Inspect Structure. Check resolution, parts, channels, AOVs, and categories before reading pixels.
  7. Run Analyze. Progress shows processed frames, and read failures are retained as findings.
  8. Review and export. Filter findings, navigate to outliers, and generate JSON or HTML.

Source interpretation

Auto

Resolves a single file, numbered sequence, or comparison set from the discovered names.

Sequence

Enables gap, duplicate, and padding validation. It does not allow numbered frames to be mixed with loose EXRs.

Comparison

Compares deliberately independent samples and avoids treating naming differences as sequence gaps.

Sequences and expected ranges

The sequence checker groups names by the final numeric block before .exr. For example, shot.0001.exr and shot.0002.exr form the pattern shot.####.exr.

Frame Limit and Expected Frame Range are different

OptionPurposeExample
Frame LimitPrevents an unexpectedly large analysis from starting.Reject the run if more than 1,000 files are discovered.
Expected Frame RangeDeclares which frame numbers must exist in one sequence.With 1–800 expected and only 1–301 present, report 302–800 as missing.

A missing frame inside the expected range is an error. Discovered frames outside that range produce a warning. Do not use this option in Comparison mode.

uv run aovguard check-sequence "C:\renders\shot" --expected-frame-range 1 800

check-sequence inspects names only; it does not decode pixels. It returns exit code 1 when frames are missing or numbers fall outside the declared range.

Interpreting results

Findings

Errors, warnings, and informational items, including the rule, AOV, channel, file, and evidence.

Metrics

Aggregate color-AOV metrics and a per-frame chart with the median and robust range.

Outliers

Samples ordered by robust score. The locate action takes you directly to the exact frame.

Frames / Samples

Luminance, non-finite values, and change relative to the median and previous frame.

Technical

Minimum, average, maximum, NaN, infinities, and negative counts for every technical channel.

Sequences

Pattern, discovered range, present and missing frames, duplicates, and padding.

Statuses

  • PASS: no active errors or warnings.
  • WARNING: conditions need review but may be valid for the shot.
  • FAIL: at least one error exists, such as a corrupt EXR, NaN/Inf data, or an incomplete expected range.

The chart can display luminance, the delta from the previous frame, or relative percentage change. Triangles mark robust outliers and squares mark frame errors.

Cryptomatte handling

Cryptomatte identification values are stored as floating-point numbers, but they do not represent color or brightness. AOVGuard reads metadata in the form cryptomatte/<id>/name to identify the base layer and its numbered layers.

  • Cryptomatte AOVs remain visible in the inventory and technical diagnostics.
  • All ID and coverage channels remain available for NaN and infinity checks.
  • They do not participate in luminance, temporal-change, brightness-outlier, or generic extreme-magnitude rules.
  • Large or negative ID values are not considered defects by themselves.
Files without metadata: if a renderer removes Cryptomatte attributes, classify the AOV through [aov_categories]. AOVGuard deliberately avoids assuming that every name beginning with crypto_ is Cryptomatte.

AOV categories

CategoryTreatment
colorLuminance, non-black ratio, temporal series, and per-channel diagnostics.
scalar, vector, mask, depthEvery component is diagnosed by channel; color luminance is not applied.
cryptomattePer-channel integrity without interpreting IDs as intensity.
unknownPreserved and flagged; never discarded silently.
ignoredAn explicit user decision; remains visible and retains integrity checks.

Rules and presets

A preset can enable rules, change severities, set parameters, and classify AOVs. Names in [aov_categories] are case-insensitive.

preset = "lighting_delivery"

[aov_categories]
custom_depth = "depth"
crypto_asset = "cryptomatte"
vendor_payload = "ignored"

[rules.nan_inf]
enabled = true
severity = "error"
supported_aov_types = ["color", "scalar", "vector", "mask", "depth", "cryptomatte", "unknown", "ignored"]

[rules.empty_aov]
enabled = true
severity = "warning"
supported_aov_types = ["color"]

[rules.extreme_values]
enabled = false
severity = "warning"

[rules.extreme_values.parameters]
max_absolute = 1000000.0

Integrity rules can apply to technical channels. Artistic rules such as empty_aov and near_empty_aov are restricted to color. The interface can save an unknown-AOV classification to the preset only after explicit confirmation.

Command line

Structural inspection

uv run aovguard inspect-structure "C:\renders\shot.0001.exr"

Analysis with JSON and HTML

uv run aovguard analyze "C:\renders\shot" --source-mode sequence --expected-frame-range 1 800 --rules-config config\rules.example.toml --json reports\shot.json --html reports\shot.html

Recursive discovery

uv run aovguard analyze "C:\renders" --frame-pattern "shot.*.exr" --recursive --max-depth 2

For safety, multiple numbered sequences require --allow-multiple-sequences. Use --max-frames 1000 as a size limit and --fail-on-warning for strict publishing.

Exit codes

  • 0: PASS, or WARNING when strict mode was not requested.
  • 1: FAIL, read/configuration error, or WARNING with --fail-on-warning.
  • check-sequence also returns 1 for an incomplete expected range.

Reports and baseline comparison

JSON is the canonical machine-readable report. It records the version, options, source, discovered/processed/failed frames, AOV inventory, metrics, series, sequences, and findings without emitting non-standard NaN/Infinity tokens.

HTML presents the same result for human review, including status, configuration, metrics, technical diagnostics, sequences, findings, and recommendations.

uv run aovguard compare-reports reports\baseline.json reports\candidate.json --json reports\comparison.json

The comparison identifies added or removed AOVs, metric changes, new findings, and resolved problems. In the GUI, analyze the candidate first and then use Compare Baseline.

Troubleshooting

“EXR contains no image parts”
The file is empty, incomplete, or corrupt. AOVGuard records a read error and continues with the remaining frames; rerender or replace that EXR.
No files are found
Check the path and Frame Pattern. Enable recursive search when EXRs are inside subdirectories, and increase Max Depth if required.
Several sequences are detected
Narrow the pattern or select a more specific directory. Enable multiple sequences only when combining them is intentional.
Cryptomatte appears as color
Check whether the file retains its cryptomatte/.../name attributes. If they are absent, assign cryptomatte through the preset.
Technical values are extremely large
They may be encoded IDs. The table uses scientific notation; decide from the category rather than magnitude alone.
The interface appears frozen
Analysis runs in a worker, and cancellation occurs after the current frame finishes. Large EXRs can take time during that read.

Known limitations

  • Deep EXR and multipart structures are detected, but the current backend does not analyze them completely.
  • The tool does not understand artistic intent; thresholds must be calibrated per production.
  • Category inference is conservative. Studio-specific names may require a preset.
  • The expected range supports exactly one numbered sequence and does not replace farm-management software.
  • Baseline reports compare AOVGuard evidence; they do not perform visual image comparison.
